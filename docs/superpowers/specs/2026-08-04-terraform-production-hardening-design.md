# Terraform Production Hardening Design

## Scope

Harden the existing Terraform defaults without adding services, changing application code, deploying infrastructure, or changing resource identity.

## WAF

Keep the existing exact-path OAuth callback rate-based rule. Add configurable rate-based rules for chat and a narrow set of expensive or security-sensitive mutation paths:

- `/api/v1/chat`
- `/api/v1/refresh`
- `/api/v1/stocks/`
- `/api/v1/persona`
- `/api/v1/notes`
- `/api/v1/conversations`

The mutation paths will be represented by a variable list and matched with an AWS WAF regex pattern set through a scope-down regex-pattern-set reference. Chat remains a separate exact-path rule with its own limit. Each rule will aggregate by source IP, block over-limit requests, and expose a distinct CloudWatch metric.

## RDS

Use safer defaults for backup retention, deletion protection, and final snapshots. Preserve the existing RDS identifier and avoid lifecycle or engine changes that could force replacement. Enabling deletion protection and final snapshots changes destructive-operation behavior but does not replace the instance. A final snapshot identifier will be generated by AWS when Terraform destroys the instance.

## Configuration And Verification

Add descriptions, validation, examples, and README entries for all new or changed variables. Add Terraform-native tests when supported by the installed Terraform version; otherwise rely on variable validation plus `terraform fmt` and `terraform validate`. Do not run `terraform apply`, AWS API calls, or deployment workflows.
